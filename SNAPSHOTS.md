# Snapshots

NeuroNet keeps working copies of old builds on GitHub Pages. The latest app is
at the site root; old builds live under `/showcase/<version>/`.

- Latest app: <https://aigsniperyt.github.io/neuronet/>
- Gallery: <https://aigsniperyt.github.io/neuronet/showcase/>
- Snapshots: `/showcase/v9/`, `/showcase/v8/`, `/showcase/v5/`, ...

## How multiple versions fit on one site

GitHub Pages serves one static site. The deploy job puts two things in it:

```text
/                       latest app from main
/showcase/              gallery (index.html + versions.json)
/showcase/v9/           frozen copy of v9
/showcase/v8/           frozen copy of v8
/showcase/v5/           frozen copy of v5
```

Each snapshot is a complete copy of the app at that ref, not an iframe or a
runtime switch. The only edits made during the copy are the ones needed to make
it run offline and keep its data separate:

| Build style | Patch |
| --- | --- |
| Current (`src/main.js`, `src/db.js`) | `APP_VERSION = "showcase-<version>"`, `DEMO_MODE = true`, backend set to `https://showcase.invalid` |
| Old (`script.js`, `db.js`) | `DB_NAME = "neuronet-showcase-<version>"`, backend set to `https://showcase.invalid` |

IndexedDB is scoped to the page origin, so all versions technically share the
same origin. They stay separate because each one uses a different database
name:

- Latest app: `neuronet-v9`
- v9 snapshot: `neuronet-showcase-v9`
- v8 snapshot: `neuronet-showcase-v8`
- v5 snapshot: `neuronet-showcase-v5`

Nothing is shared between them. Importing, deleting, or studying in one version
does not touch another version or the latest app.

## Branches

- `main` contains the latest app, the build script, and the workflow.
- `showcase` contains only generated output: `index.html`, `versions.json`,
  `.nojekyll`, and one folder per version.

Do not edit files inside a version folder on `showcase` by hand. They are
regenerated by the build. The only manual edits there are updating
`versions.json` and deleting a folder when removing a snapshot.

## Pipeline

The workflow is `.github/workflows/pages.yml`. It runs on every push to `main`
and on manual `workflow_dispatch`.

For a manual snapshot run:

1. Check out `main` as `dist`.
2. Check out `main` as `workflow-src` (the build script and seed template).
3. Check out `showcase` as `showcase`.
4. Check out the requested `ref` as `snapshot`.
5. Run `scripts/build-showcase.mjs`:
   - copy the snapshot into `showcase/<version>/`,
   - patch the database name, demo mode, and backend URL,
   - copy `demo-data.json` if the snapshot does not already have one,
   - generate `showcase-seed.js` and add it to the snapshot's `index.html`,
   - write `showcase-meta.json`,
   - update `versions.json` and regenerate the gallery.
6. Commit the result to `showcase`.
7. Assemble the Pages artifact: latest app at the root, `showcase/` copied to
   `/showcase/`.
8. Deploy to GitHub Pages.

The gallery is generated from `versions.json`, so it always matches the folders
that exist on `showcase`.

## Demo seeding

Every snapshot is built with a `showcase-seed.js` file and a `demo-data.json`.
The seed script runs once in the browser on first load:

1. Wait for the app to create its IndexedDB schema.
2. Check every store the build knows about.
3. If any store already has records, stop. Existing data is never overwritten.
4. Fetch `demo-data.json`.
5. Write nodes, quotes, cues, cards, tags, and heaps, but only to stores that
   exist in that version.
6. Set a session flag and reload once so the app reads the new data.

The tag store is rebuilt from node, quote, and card tags. Card-first builds also
get starter heaps: one with all demo cards, plus a technique/character subset
when it is smaller than the full set. Old builds ignore cards and heaps because
those stores do not exist.

The seed is deliberately per browser. It does not ship personal data to the
repo and it does not use a server. Clearing site data resets a snapshot to its
seeded state. The session flag is `neuronet-showcase-seeded:<version>`; clear it
if you want to force the seed check again in the same tab.

If a snapshot branch has its own `demo-data.json`, the build uses that file.
Otherwise it uses the canonical `demo-data.json` from `main`. That is how v8 and
v5 get the current demo dataset even though those branches predate it.

## Add or update a snapshot

Use the GitHub website; no local checkout is required.

1. Open the repo on GitHub.
2. Go to **Actions** → **Deploy NeuroNet showcase**.
3. Click **Run workflow**.
4. Keep **Use workflow from** set to `main`.
5. Fill in the inputs:

| Input | Meaning | Example |
| --- | --- | --- |
| `ref` | Branch, tag, or commit to freeze | `main`, `v8`, `demo-v10`, `a1b2c3d` |
| `version` | Folder name under `/showcase/` | `v10` |
| `label` | Card title in the gallery | `v10 — card-first` |
| `description` | One-line card description | `Cards, heaps, and the new graph.` |

6. Run it and wait for the Pages deployment to finish. Propagation usually
   takes 30–90 seconds, but Pages can cache for up to about 10 minutes.

Examples:

- New snapshot from the current app: `ref=main`, `version=v10`.
- Old branch: `ref=v8`, `version=v8`.
- Tagged build: `ref=demo-v9`, `version=v9`.
- Update an existing snapshot: run again with the same `version`. The folder is
  replaced and the `versions.json` entry is updated.

Leave `version` blank only when the auto-detected name is what you want. For a
`main` snapshot, auto-detection reads `window.APP_VERSION` (currently `v9`), so
set `version` explicitly when adding a new version from `main`.

Tags do not auto-deploy. GitHub Pages environment protection only allows
deployments from `main`, so a tag push is rejected. Always start the workflow
from `main`; the `ref` input can still point at a tag or commit.

## Remove a snapshot

1. On the `showcase` branch, delete the version folder (for example `v8/`).
2. Remove its entry from `showcase/versions.json`.
3. Trigger a deploy from `main` by pushing a commit (even a small docs change).
   Do not re-run a manual snapshot run with that version, or it will be added
   back.

## Local build

Build one snapshot into a temporary directory:

```bash
git worktree add --detach /tmp/neuronet-v8 v8

SHOWCASE_DIR=/tmp/neuronet-showcase \
SNAPSHOT_DIR=/tmp/neuronet-v8 \
VERSION=v8 \
REF=v8 \
COMMIT="$(git -C /tmp/neuronet-v8 rev-parse --short HEAD)" \
LABEL="Pre-card-first UI" \
DESCRIPTION="The last build before cards became the study unit." \
node scripts/build-showcase.mjs
```

Serve it on port 5500, because the app whitelists `http://127.0.0.1:5500`:

```bash
python3 -m http.server 5500 --directory /tmp/neuronet-showcase
```

Then open <http://127.0.0.1:5500/> for the gallery or
<http://127.0.0.1:5500/v8/> for the snapshot. The seed runs on first load and
reloads once. If port 5500 is busy, use another port and add it to
`ALLOWED_ORIGINS` in the snapshot's `script.js` or `src/main.js`.

To check seeding, open DevTools → **Application** → **IndexedDB** and look for
`neuronet-showcase-v8`. The stores should contain the demo records. The console
logs `[showcase] demo seed skipped: ...` if seeding could not run.

## Files

- `scripts/build-showcase.mjs` — copy, patch, seed, gallery, `versions.json`.
- `scripts/showcase-seed.template.js` — browser-side seed script template.
- `.github/workflows/pages.yml` — deploy and manual snapshot workflow.
- `demo-data.json` — canonical demo dataset.
- `showcase` branch — generated gallery and snapshots.
- `SNAPSHOTS.md` — this file.

## Caveats

- Snapshots are frozen at the commit they were built from. They do not receive
  later app fixes. Rebuild the snapshot to update it.
- The latest app at `/` is not frozen; it updates on every push to `main`.
- `showcase` is public. Do not put personal study data there.
- Old versions log a DNS error for `https://showcase.invalid`. That is expected:
  the backend is intentionally disabled, and the app catches the failure.
- The Actions Node 20 deprecation warnings are harmless.
- If a future version adds a new store that should be seeded, add it to
  `detectDemoStores()` in `scripts/build-showcase.mjs` and to the seed logic in
  `scripts/showcase-seed.template.js`.
